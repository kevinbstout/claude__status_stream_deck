# Architecture

Technical reference for working on this plugin. For what it does and how to install it, see the
[README](README.md).

## Design constraints

These are structural, not stylistic. Changing any of them changes what the product is.

1. **No network access.** No `fetch`, no `http`/`https`, no sockets, in the plugin, the shim, or any
   dependency. Every figure comes from a file already on disk. `npm run audit:offline` enforces this
   as a build gate.
2. **No credential access.** Never read `.credentials.json`, the OS keychain, Windows Credential
   Manager, `ANTHROPIC_API_KEY`, or any token. The plugin never authenticates as the user.
3. **No child processes.** No `spawn`, no `exec`, no shelling out.
4. **Read-only** on all Claude data. The single write is the opt-in `settings.json` statusline patch,
   which backs up first and is reversible from the Property Inspector.

Consequence worth internalising: **limit percentages are only ever read, never derived.** The plan's
true denominator is not knowable locally, so token counts can never be turned into a percentage. When
no source reports a percentage, the UI shows `--`. A confidently wrong number is worse than no number.

## Stack

- TypeScript, strict mode
- `@elgato/streamdeck` v2 (`SingletonAction` subclasses, `@action({ UUID })` decorators)
- `@elgato/cli` for `validate` and `pack`
- **Runtime dependencies: none beyond the SDK**
- Dev only: `typescript`, `rollup`, `vitest`, `sharp` (icon rasterisation at build time)
- Cross-platform paths via `os.homedir()` and `path.join()`; never hardcode a separator

## Data sources

The plan allowance is shared across Claude desktop, claude.ai and Claude Code. Two local sources
report it, and they are complementary rather than redundant.

### 1. Claude desktop usage history — primary

`plan-usage-history.json` in Claude desktop's application data folder, sampled every five minutes:

```json
{ "version": 2, "samples": [{ "t": 1784639187219, "org": "…", "u": { "fh": 20, "sd": 2 } }] }
```

`t` is epoch milliseconds, `fh` the 5-hour window and `sd` the 7-day window, both integer percentages
0–100. This covers the whole plan regardless of which Claude surface consumed it, needs no setup, and
retains days of history — which is what makes the burn rate a measurement rather than a guess.

**Locating it on Windows is not obvious.** When Claude desktop is installed as a packaged (MSIX) app,
`%APPDATA%\Claude` is a redirection link and the real data lives at
`%LOCALAPPDATA%\Packages\Claude_*\LocalCache\Roaming\Claude`. Processes that do not resolve the link
— Stream Deck's plugin host among them — do not see the folder at all, and `statSync` returns
**ENOENT rather than EACCES**, which is indistinguishable from a genuinely missing file.
`claudeDesktopCandidates()` probes both, matching the package folder by prefix because it carries a
publisher hash.

Samples carry an `org` id. Signing into a different account leaves both accounts' samples interleaved
in one file, so rate measurement is scoped to the account of the most recent sample.

### 2. Claude Code statusline — optional

Claude Code passes a JSON payload to a user-configured statusline command. It reports the same
percentages but only while Claude Code is running, and adds what desktop does not record: **window
reset times**, context usage, and the model name.

Two conditions govern availability: `rate_limits` appears only for Claude.ai Pro/Max subscribers, and
only after the first API response in a session. Claude Code reads `settings.json` at startup, so
installing the hook has no effect until it restarts.

### 3. Transcripts — API cost only

`~/.claude/projects/**/*.jsonl`, parsed for token counts. Never used for allowance percentages.

## Tolerant probing (`core/pluck.ts`)

The statusline payload shape has changed repeatedly and will again, so nothing binds to a single
path. Every read goes through a candidate list, taking the first that resolves non-null.

Two normalisations matter:

- **Reset timestamps** arrive as ISO strings *or* epoch seconds. A number below `1e12` is seconds —
  the millisecond epoch passed `1e12` in 2001, so anything smaller cannot be one.
- **Percentages** are sometimes fractional (`0.73`) and sometimes not (`73`). A value in `(0, 1]` is
  rescaled **only** when a sibling metric is also `<= 1`. Without that corroboration a legitimate
  0.5% would become 50%.

## Transcript parsing (`core/jsonl.ts`)

Walk recursively for `*.jsonl` and read line by line through a streaming reader; these files reach
several MB and must never be loaded whole. `JSON.parse` each line in a try/catch and skip failures —
partial trailing lines are normal on a file being appended to.

**Deduplicate on `${message.id}:${requestId}`**, falling back to
`${timestamp}:${inputTokens}:${outputTokens}`. The same message appears across transcripts when a
session is resumed or forked, and twice within a single file when a request streams more than one
frame. In practice this removes over half of all usage lines; skipping it roughly doubles every
reported figure.

Files are cached by path + mtime + size, so a refresh only re-parses what changed. Budget: cold parse
under two seconds across 500 files, warm refresh under 100ms.

## Cost (`core/pricing.ts`)

A pre-computed cost field is used verbatim and marks the rollup `exact`. Otherwise it is estimated
from `pricing.json` — shipped beside the plugin, user-editable, keyed by case-insensitive model
substring with longest-match-wins and a `default` fallback. Rates are USD per million tokens across
input, output, cache write and cache read.

Any rollup containing one estimated entry is marked `estimated`, and every surface showing it prefixes
`~`. **Never present an estimate as exact.**

Note this figure is API list-price value, not subscription spend. On a Pro or Max plan it is not money
the user pays, which is why every label leads with "API".

## Five-hour blocks (`core/blocks.ts`)

Sort ascending. Open a block at the first entry floored to the hour; run it for five hours. A new
block opens when an entry falls at or past the current block's end, or when five hours pass with no
entries at all. At most one block contains `now`.

## Snapshot (`core/snapshot.ts`)

The single object every action reads. Percentages come from whichever source is fresher; reset times,
context and model come from the statusline whenever it has them.

**Pace** compares consumption against window position:
`pace = usedPct / max(elapsedPct, 1)`, with `windowStart = resetsAt - windowLength`. Without a reset
time there is no window position, so pace is `undefined` and the UI hides it.

**Burn rate** is percentage points of allowance per hour, measured across the sample series within a
90-minute lookback requiring at least a 15-minute span. A flat or falling series returns zero — both
windows roll and decay when idle, and a negative rate would project a cap in the past. Where only the
statusline is available, the rate falls back to `usedPct / elapsedHours`, suppressed below five
minutes elapsed where the divisor is meaningless.

**Projection** is `remaining / rate`, which needs no reset time. A projection landing after a known
reset is discarded — the window refills first. `binding` names whichever window is projected to cap
first, and is what the allowance-burn metric displays.

**Staleness** is source-aware: five minutes for the statusline, twelve for desktop. Desktop samples
every five minutes, so the tighter threshold would flash "stale" in the gap before each sample.

## Poller (`core/poller.ts`)

One shared loop for the whole plugin, not one per action instance. Recomputes every 5 seconds and on
every state file change, then emits to subscribers. Actions subscribe on `onWillAppear` and
unsubscribe on `onWillDisappear`; the loop starts with the first subscriber and stops with the last.
Identical consecutive snapshots are not emitted — Elgato caps programmatic updates at 10 per second.

## Actions

UUID prefix `com.revductive.usage-meter`. **UUIDs are permanent after publishing.** To retire an
action, clone it and hide the original via `VisibleInActionsList`; never rename.

| Action | Controllers | Settings |
| --- | --- | --- |
| `.meter` | Encoder, Keypad | `metric`: `five_hour` \| `seven_day` \| `allowance_burn` \| `context` \| `cost_today` \| `cost_rate`; `compact` |
| `.dual` | Encoder | none — always session over weekly |
| `.spend` | Encoder, Keypad | `window`: `today` \| `week` \| `month` \| `block` |
| `.alert` | Keypad | `metric`, `warnAt` (70), `criticalAt` (90), `lastBand` |

Rotate cycles the metric or window; press refreshes; touch tap toggles detail; a held touch opens the
usage page. `.dual` has no rotate by design. `.alert` fires `showAlert()` once per upward band
crossing, tracked via `lastBand` — a key that pulses continuously trains users to ignore it.

Shared configuration lives in global settings so each Property Inspector stays simple.

## Rendering

### Touch strip layouts

Canvas is **200 × 100 px**. Any item whose `x + width` exceeds 200 or `y + height` exceeds 100 makes
Stream Deck **silently refuse to load the entire layout** — no error, just a blank strip. Run
`streamdeck validate` after every layout change.

**Never name a layout key `title` or `icon`.** Both are reserved: whatever the user types into the
Stream Deck app wins and silently clobbers the plugin's text. That is why the heading key is
`heading`.

Update with partial payloads — omitted keys retain their previous values:

```ts
setFeedback({ value: "73%", indicator: { value: 73 } })
```

### Keypad gauge (`render/gauge.ts`)

A 144 × 144 SVG string. A 270° arc sweeps from bottom-left clockwise over the top to bottom-right,
centre `(72, 66)`, radius 48. Below 0.5% no progress arc is drawn at all, because a zero-length arc
still paints its round line cap as a stray dot on the track.

Stale readings render at `opacity="0.4"` with a clock glyph; touch strip headings prefix `○ `.

### Colours

```
ok        #00c853   pct < 70
warn      #f4b675   70 <= pct < 90
critical  #d50000   pct >= 90
track     #2a2a2a
text      #ffffff
muted     #8a8a8a
```

Pace glyph: `▲` above 1.3, `●` from 0.8 to 1.3, `▼` below 0.8.

## Statusline shim (`bin/statusline-hook.mjs`)

Standalone ESM with zero dependencies, importing nothing beyond `node:fs`, `node:path` and `node:os`.
It runs under whatever Node is on the user's PATH, outside the plugin bundle, so it duplicates the
candidate-path logic inline rather than importing from `src/`.

It reads stdin, writes the state file **atomically** (write to `.tmp`, then rename, so the plugin can
never read a half-written file), and prints a one-line status so the user still has a statusline.

**It must never throw.** Every error path still prints something and exits 0, or the user's statusline
breaks and the plugin gets the blame.

### Installer (`hook/install.ts`)

Backs up `settings.json` before any write and restores it byte-for-byte on removal. Installing twice
is a no-op. If a foreign `statusLine.command` is already configured it **refuses** rather than
overwriting: the shim cannot chain to another command without spawning a child process, so silently
replacing it would break the user's setup. Non-destructive by refusal.

## Property Inspector

One HTML file serves all four actions, revealing controls by action UUID on DOM ready to avoid
flicker. It is hand-written rather than using `sdpi-components`, which loads from an external host and
would breach the no-network constraint.

Elgato requires: auto-save on change with **no Save button**, checkboxes for booleans, selects for
single-select, validation feedback, and **no donation or sponsor links** — those belong in Additional
Links on the Marketplace listing.

## Manifest

- `SDKVersion` must be `2` and `Nodejs.Version` must be the string `"20"`. The validator pins both;
  the CLI scaffolds a newer Node version that `streamdeck validate` rejects.
- Category and action icons must be **monochrome white `#FFFFFF` on transparent**. Colour or a solid
  background is an automatic rejection. The plugin icon may use colour.
- `Author` must match the Marketplace organization name exactly.

Icon sizes: plugin 256/512, category 28/56, action 20/40, key state 72/144. Emit `name.png` and
`name@2x.png`; reference them in the manifest **without** the extension.

## Testing

```bash
npm run typecheck && npm test && npm run audit:offline && npm run validate && npm run pack
```

`npm run diagnose` prints what the plugin would see on the current machine — which sources resolved,
parse timings, and the resulting figures. It is the fastest way to tell a data problem from a render
problem.

Pure functions carry the test weight: probing and normalisation, block boundaries, transcript dedupe
and cost exactness, formatting, snapshot merge and projection, gauge geometry, and the settings
backup/restore round-trip against a temporary directory.

## Implementation notes

Hard-won behaviours that are easy to rediscover the slow way.

- **Never await a Stream Deck round-trip before painting.** `getSettings()` and `setSettings()` are
  websocket calls, and awaiting either in a render path can leave a dial frozen on its first frame.
  Settings arrive with `willAppear` and `didReceiveSettings`, so they are cached per action instance;
  `applySettings()` caches, repaints, then persists without awaiting.
- **Connect before requesting anything.** Asking Stream Deck for global settings before
  `streamDeck.connect()` resolves leaves a promise that never settles; with nothing holding the event
  loop open, Node exits with code 13 and Stream Deck restarts the plugin in a loop until it disables
  it. Startup work that is not essential should not be top-level awaited.
- **`streamdeck restart` does not reliably reload a running plugin.** The command is accepted with no
  effect. Stopping the plugin's `node20.exe` process directly forces a genuine reload; Stream Deck
  relaunches it within about ten seconds.
- **Watch the directory, not the state file.** The shim writes atomically via rename, so a file watch
  ends up pointing at a replaced inode. A periodic re-read backs up the watcher, which silently stops
  delivering events on some Windows configurations.
- **`Set-Content -Encoding utf8` on PowerShell 5.1 writes a BOM.** A BOM in `manifest.json` makes
  `streamdeck pack` fail with an unreadable minified stack trace.

## Known limitations

- **Reset countdowns require the statusline hook.** The desktop usage record stores only percentages
  and timestamps, so users who do not run Claude Code see burn rate and projection but no countdown.
- **The desktop usage file is undocumented.** Its shape or location may change in any release. The
  parser is defensive and degrades to `--` rather than displaying wrong numbers, but this is the main
  fragility in the design.
- **macOS is implemented but unverified.** The packaged-app redirection described above is
  Windows-specific; the macOS path is the conventional Application Support location.
- **Claude Code only** for transcript-derived cost. Other agent CLIs are not parsed.
